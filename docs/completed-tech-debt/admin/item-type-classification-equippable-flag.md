# Item Type Classification: Equippable Flag

## State

Complete

## Summary

`HeldItem` has no `equippable` flag, so the system cannot distinguish between items that can be held by a pokemon in battle and items that exist only in a player's inventory (e.g. potions, key items added in the future). Without this classification, the `ItemSearchDropdown` in `PokemonSlotEditor` would show non-equippable inventory items when the player tries to assign a held item to a pokemon. The seed script and shared type both need updating to carry this flag forward from item creation through to UI filtering.

## Problem Details

**File:** `packages/shared/src/types/pokemon.ts:82-87`

```typescript
export interface HeldItem {
  id: string;
  name: string;
  effectId: string;
  isBerry: boolean;
  // ← no equippable field
}
```

**File:** `data/scripts/seed.ts:160-165`

```typescript
const allItems = gen9.items.all().map((i) => ({
  id: i.id,
  name: i.name,
  effectId: i.id,
  isBerry: !!i.isBerry,
  // ← equippable not written; @pkmn/dex Item has flags that could inform this
}));
```

All items currently in `data/items.json` are competitive held items sourced from `@pkmn/dex` Gen 9 data, so all are equippable. The flag is needed now so that non-equippable items added later (e.g. healing items, trainer-use consumables) are correctly excluded from the pokemon slot editor without requiring a schema migration later.

**File:** `packages/client/src/admin/ItemSearchDropdown.tsx:1-105`

The dropdown fetches all implemented items via `data:query items` and has no mechanism to request only equippable items. Once non-equippable items exist, they will appear here.

**File:** `packages/server/src/socket/handlers/adminHandlers.ts:101-112`

The `data:query items` handler filters to `IMPLEMENTED_ITEM_IDS` only; it has no `equippable` filter parameter.

## Impact

- No way to prevent non-equippable items from appearing in the pokemon held-item dropdown once they are added to the system.
- Inventory items (potions, etc.) added in the future would bleed into the pokemon slot editor without this gate.
- `HeldItem` schema is missing a semantically meaningful field that downstream plans (inventory-constrained equipping, species restrictions) assume exists.

## Suggested Fix

1. Add `equippable: boolean` to `HeldItem` in `packages/shared/src/types/pokemon.ts`.

2. Update `data/scripts/seed.ts` item mapping to include `equippable: true` for all items sourced from `@pkmn/dex` (all Gen 9 competitive items are equippable held items). Non-equippable items added manually later should set `equippable: false`.

3. Update `data/scripts/validate.ts` if it validates item schema, to require the `equippable` field.

4. Re-run `pnpm seed` to regenerate `data/items.json` with the new field.

5. In `packages/server/src/socket/handlers/adminHandlers.ts`, extend the `data:query items` case to accept an optional `equippableOnly?: boolean` param and filter accordingly:
   ```typescript
   const { query: itemQuery, equippableOnly } = payload.data as { query?: string; equippableOnly?: boolean };
   const filtered = allImplemented.filter((i) => !equippableOnly || i.equippable);
   ```

6. In `packages/client/src/admin/ItemSearchDropdown.tsx`, accept an `equippableOnly?: boolean` prop and pass it in the `data:query` payload. `PokemonSlotEditor` should always pass `equippableOnly: true` when rendering the held-item picker.
