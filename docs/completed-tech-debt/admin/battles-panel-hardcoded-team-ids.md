# 18 — `BattlesPanel` Hardcodes Team IDs for Winner Lookup

## State

Complete

## Summary

The `winnerLabel()` function in `BattlesPanel` maps the stored `winningTeamId` to a team array index using a hardcoded string comparison. If the team IDs generated by `BattleConfigurator` ever differ from `'team-a'` / `'team-b'`, the wrong team name is displayed (or no name at all) in the past battles history.

## Problem Details

**File:** `packages/client/src/admin/BattlesPanel.tsx:63`

```ts
function winnerLabel(battle: BattleSummary): string {
  if (!battle.winningTeamId) return '—';
  const teamIndex = battle.winningTeamId === 'team-a' ? 0 : 1;
  const team = battle.teams[teamIndex];
  return team ? team.slots.map((s) => s.displayName).join(' & ') : battle.winningTeamId;
}
```

This logic assumes that `'team-a'` always maps to index 0 and everything else maps to index 1. If team IDs are UUIDs or any other value, the else branch always picks index 1 regardless of which team actually won.

## Impact

- Past battles may show the wrong winner name in the admin battle history
- Particularly likely to break if the battle configuration system is ever extended to support custom team IDs
- Graceful degradation exists (falls back to raw `winningTeamId` string), but that's not user-friendly

## Suggested Fix

Use `Array.find` to look up by team ID rather than index arithmetic:

```ts
function winnerLabel(battle: BattleSummary): string {
  if (!battle.winningTeamId) return '—';
  const team = battle.teams.find((t) => t.teamId === battle.winningTeamId);
  return team ? team.slots.map((s) => s.displayName).join(' & ') : battle.winningTeamId;
}
```

This requires `BattleSummary.teams[n]` to include `teamId`. Verify the `BattleSummary` type in `@poke-fighter/shared` and the DB query that populates it include this field.
