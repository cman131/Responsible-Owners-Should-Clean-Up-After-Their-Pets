Three targeting UI modes

After clicking a move, the targeting area below the move panel shows one of three states depending on the move's target type. All three use the same Confirm + Cancel buttons.

Mode 1 — CHOOSE (normal, any, adjacentFoe, adjacentAlly, adjacentAllyOrSelf)
Target:

Dropdown is populated with legalTargets for this specific move (already adjacency-filtered by server). User picks one, then clicks Confirm.

Mode 2 — LISTED (allAdjacentFoes, allAdjacent, allies)
Targets: Blaziken, Lucario, Gardevoir...

Names from legalTargets, capped at 3 with trailing "…" if more. Read-only — no dropdown. Confirm submits.

Mode 2 — LISTED (≤ 3 targets, no ellipsis)
Targets: Blaziken, Lucario
Mode 3 — LABELED (all → "All", allyTeam → "Ally team", randomNormal → "Random", etc.)
Targets: All
Targets: Ally team
Targets: Random

Static label — no slot names, no dropdown. Confirm submits with no targetSlotId (server resolves the target).

Mode 4 — AUTO (self, scripted) — no UI shown
No targeting UI — action submitted immediately on move click

Self-targeting moves (Swords Dance, Roost) and scripted moves (Counter) submit instantly — no targeting step, same as the current single-target fast path.
